- **Agent secret requests** (2026-10-30, flag `agent_secret_request`, off by default): when a command needs an API key or token, the agent calls `request_secret` on the Switchboard MCP server instead of asking for it in chat. Details in `src/main/mcp/AGENTS.md` (Secret requests) and `docs/feature-parity/agent-secret-request.json`.
  - **What the user sees.** A card in the chat says the agent asks for a secret, with the agent's title, its instructions as plain text (each link's host in bold), a masked input, Save securely and Decline. Save writes the value to a private 0600 file in a folder for that chat only; the agent gets the file path and the env var `SWITCHBOARD_SECRETS_DIR`, never the value. The card then turns into one line (Saved, Declined or expired) with the time left, Extend and Delete now.
  - **Desktop only entry.** Only the desktop answer channel can save a value. The phones (Expo and Android) show the card read-only, with "Answer this on your computer" and Decline, and the push text names only the chat. Entry on a phone is a later change (capability `agent_secret_phone_v1`).
  - **Lifetime.** A file lives 24 hours unless the agent asked for less (15 minutes, 1 hour or 4 hours). Extend sets it to 24 hours from now; Delete now removes it at once. Archiving the chat, or removing its project, closes an open card and deletes its files; if that delete fails, the next sweep (at start and every 15 minutes) retries it.
  - **What it cannot promise.** When a command reads the file, the value is in that process: if the command prints it, the model sees it. Switchboard masks a saved value (and its base64 forms, and the value URL-, form-, JSON- or shell-escaped) in chat, stored rows, search, history and its own logs while the file lives. A value it masked at least once stays masked in that chat's history after the file is deleted, expires or is replaced (kept sealed by the OS keychain, removed with the chat). Switchboard cannot change what the model saw, the agent provider's own transcript file, files the agent wrote or commits. Values under 8 characters are not masked. The file mode stops other OS users, not other processes of the same OS user. Switchboard refuses to write through a secrets folder that is a symlink or that another user owns, but a same-user process can still swap a folder between that check and the write. On Windows the file mode is not enforced: only the user profile's own permissions protect the file, there is no backup exclusion, and a roaming profile can copy it; the card says so. On macOS the folder gets a Time Machine exclusion, which is checked after it is added; if it fails, Save still works, the card says the file is not excluded, and each sweep and each start try again. The exclusion does not apply to other backup tools. On an SSH machine the file stays on that machine, under its own data folder; its disk and backups are outside Switchboard's control. Swap and hibernation files are out of scope.

## What's NOT working yet

- **Production signing credentials** - complete credential sets enable signing; absent sets keep the unsigned lane and partial sets fail. Source code does not establish which credentials are currently configured.
- **Codex / OpenCode native fork limits** - Codex cannot fork natively at a user message or mid-turn (turns are atomic); OpenCode only forks natively at the latest reply and never into a new worktree, and chats older than OpenCode session recording (or whose session was replaced) keep the handoff. A fork that fails to commit leaves an unused OpenCode session behind (ACP cannot delete one); a forked Codex rollout is deleted
